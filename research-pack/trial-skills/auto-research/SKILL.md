# 自动推进研究

标准入口是 `/auto-research`；自然语言中误写 `/auto-resaech` 也按此意图理解（不声称宿主注册了拼写别名）。用户只给命令和资料时，以当前工作区为范围，从真实材料和已完成产物恢复进度，自行判断最有价值且当前可推进的下一步。你是调用现有 Skill 的 Agent，不是新执行引擎；不要只返回计划或要求用户依次输入命令。

## 从当前状态开始

先读工作区规则、目标、材料目录、已有 Wiki、TAILOR.md、RESEARCH-DAG.md、EXPERIMENT-PLAN.md、STORY-PLAN.md 及真实运行记录。目标能从材料中明确得出时，简短说明理解后继续；空工作区或多个互不相容目标无法判断时，只问必要问题。访问范围限当前工作区与用户明确给出的路径，默认允许为当前研究联网搜索、访问与下载公开论文和官方代码，用户说不联网或限制来源时遵守；不再询问是否允许联网。不上传私有论文全文、数据或凭证，用必要的公开题名、作者、DOI、方法名检索。宿主权限仍须遵守。

先检查材料清单，再确定是否有数据；不能因根目录没有标准产物就宣称没材料。复用已有有效方案、结果、标识和版本。断点恢复先核对仍在运行的进程、Wiki journal 和待回流项，不重复启动实验，不静默回滚或覆盖人工修改。

## 选择并执行下一步

从本 Skill 同级目录按需读取下列 SKILL.md，实际使用其中的工具与交付协议。缺失时明确报告并继续不依赖它的工作，不假装调用成功。

| 当前需要 | 使用的 Skill | 继续方向 |
| --- | --- | --- |
| 首次整理、材料变化、未完成覆盖 | ../wiki-maintain/SKILL.md（同时读其 RUNTIME.md） | 更新知识与问题，再判断方案/证据缺口 |
| 从材料找 idea、目标对齐、选择基线和模块 | ../academic-tailor/SKILL.md | 自主推荐并选取可推进的候选用于设计，保留建议/代选状态；不伪称用户选定 |
| 安排验证、分析已有结果、已获授权的执行 | ../experiment-design/SKILL.md | 可比较证据、失败复盘、下一步；计划和运行分开 |
| 有方案或已有结果，需要讲清意义 | ../research-story/SKILL.md | 简短的为什么/问题/解决/证据，以及主张边界 |
| 理解缺口影响研究，或用户要求学习 | ../research-guide/SKILL.md | 必要的阅读与解释；练习可选，不等待答题阻塞其他研究 |

这不是固定五步流水线。已有实验先分析再讲故事，不为凑流程重跑；没有实验可先交付待验证故事。仅有论文时从材料提出可检验候选，不把拼接当已证实创新。持续推进有依据的独立任务，直到本轮可做部分完成、达到已知资源边界，或确有关键输入/方向取舍需要用户判断。不要自行无限迭代找 idea 或优化到“显著成功”。

## 自主推进与必要确认

常规检索、下载公开资料、拆解、写方案、分析已有结果、Wiki 维护、工作台自检直接进行；不要求用户在提示词重复这些步骤。可撤销且成本明确的小样本检查或低成本实验可以自行完成，先记录输入、预算和停止条件；无法判定资源成本时先估算，不能擅自启动完整训练。已有有效结果优先复用，不为流程而重跑。

有实质不同且影响目标的研究分支时，先给简短推荐和取舍再集中问一次。用户说“不用问／放手／你决定”即允许在研究范围内代选，记录理由并继续；不反复确认，不伪称用户亲自选定。缺少关键数据或环境时标记阻塞，继续独立任务。

高风险操作包括未获具体授权的付费或大额资源消耗、长时间训练/独占资源、破坏性覆盖/删除、上传私有材料、发布及影响共享系统的变更。执行前说明具体动作与影响并取得相应授权；泛称“放手”不自动覆盖这些风险。用户已具体授权某动作和预算则不重复询问。论文正文、公式和结论改动仍遵守工作区写作确认要求。

## 从一篇论文自主扩展

输入毕业论文或多项工作时，先按研究问题、章节与贡献拆出多项工作，调用 academic-tailor 的多工作拆解和原论文溯源规则。自行沿参考文献追查每项工作的基线、模块原论文与官方代码，并做问题驱动的少量扩展；下载和实际阅读的新材料加入 Wiki 增量维护。区分原模型组件、论文作者改动与本轮新提议，不将所有章节强凑一个 A+b+c。

默认生成两种互不混用的关系表达：TAILOR.md 中的模块/方法数据流（含共享基线、复用组件、跨章耦合）；RESEARCH-DAG.md 中的实际研究任务与依赖。用户无需专门要求 DAG。新增候选说明来源、要解决的缺口、接入位置与最小验证；达成一条有依据且可验证的推荐路径就推进，不无限追文献。非开放获取或付费墙论文拿不到全文时，按 academic-tailor 的摘要替代规则获取实际摘要，标“仅摘要已读”并继续筛选与设计，不因此卡住整个流程或要求用户购买。全文/代码缺失只阻塞依赖其细节的步骤，不靠标题或摘要补造模块实现。

## Wiki 与 PDF 无需用户安排步骤

首次按 wiki-maintain 全量盘点当前范围，维护时全量核对清单，仅重读变化/未完成材料及受影响页面。排除凭证、依赖、宿主配置、输出历史；未支持或失败的来源保留在覆盖账本，不能静默抽样。

遇到 PDF 按 wiki-maintain 的 PDF 准备说明和 RUNTIME 执行：先检查已有页侧车/解析器，用可用本地工具完成逐页提取；大 PDF 不要求用户压缩。保存原件哈希和物理页定位，图片/表格重要时核对视觉内容。确实没有解析/OCR 能力则说明影响，继续其他材料，不宣称完整覆盖。

实验分析/计划与故事保存后，执行各自的默认 Wiki 增量回流；回读状态，区分已提交、未变和待同步。只提交本轮实际更新的 sourceContexts，先检查 dryRun 影响，不重写无关语境。叙事不是性能的独立证据，不把 Wiki 输出再次摄入。同步失败只重试同步，不重跑实验；无变化时不制造新提交。

## 交付前自检与工作台

没有工作台时也直接给出文件路径。

复用现有文件与 trace 记录完成、受阻、待验证和下一步，不新增总状态数据库。DAG 存在时按 academic-tailor 的自检入口检查依赖；核对计划/运行/主张状态与文件一致，保留首错，不自行把失败改成通过。

用户明确不用工作台，或未安装工作台（例如 --no-workbench）时，直接交付 Markdown/Mermaid 与文件路径，不补装、不启动 UI；这属于正常纯 Skill 模式，不报告工作台故障，文件/DAG/引用自检仍执行。已安装且用户未禁用时，有产物就按下游 Skill 的“交付展示”启动或复用同工作区工作台，并为真实运行和复盘目录传入 --paths。核对 launcher 返回的绑定身份；有浏览器工具时检查本轮有产物的页面是否可读、关键计数和标签是否与文件一致。没有浏览器时可用 HTTP/API 核对绑定与投影，并明确视觉交互未测。不能仅凭启动成功宣称工作台全部验收通过。

普通研究只做上述与本轮产物相关的自检，不自动运行破坏性回滚负例、全套发布测试或停掉其他人的服务。工作台不可用时给真实错误和 Markdown 路径，研究产物仍有效。最后给用户：推进到哪、证据与 Wiki 同步情况、可用工作台/文件入口、唯一最需要其处理的下一步。只有真实审批或缺输入才停，不以“要我继续吗”结束可推进的工作。
