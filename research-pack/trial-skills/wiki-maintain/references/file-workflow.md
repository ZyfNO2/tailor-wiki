# 文件工作流

本文定义可观察的行为与最少信息，不固定某个宿主 API 或数据库。工程已有文件格式时沿用并明确映射；不要创建并行的权威数据副本。

## 文件角色

| 文件 | 记录什么 | 边界 |
| --- | --- | --- |
| 用户原始材料 | 论文、笔记、实验配置和指标 | 只读；不因整理 Wiki 改动 |
| 来源清单/证据文件 | 稳定 source ID、原路径、内容 hash、版本、读取状态、原文定位；必要时保存提取文本快照 | 清单不是事实证据；对应原文或快照才是 |
| Wiki Markdown | 稳定 page ID/slug、标题/别名、版本、正文、引用与未解决问题 | 知识整理产物；事实必须回到来源 |
| 历史与 trace | 旧版快照，运行 ID、输入版本、阶段、变更、错误、提交状态 | 记录真实操作，不能预写成功 |
| 索引/链接图 | 页面导航与关系 | 可重建的展示投影 |

新项目可用 workspace 下的 wiki/ 作为输出根：index.md、pages/、sources/、history/、runs/。这只是默认布局；已有工程运行助手可采用其他等价路径。相对链接应能随目录整体移动。

已有项目由 Core 管理时，不绕开它直接修改其内部 JSON。要采用本 Skill 的文件流程，使用用户选定的独立文件根，或工程明确提供的单向导出/适配；不要声称文件已自动同步回旧工作台。

## 来源与引用

- source ID 表示材料身份，revision/hash 表示内容版本，二者分开。已确认同一文件更新保留身份；仅 hash 相同不能自动认定两个来源独立，不能双算证据。
- 重命名只有在路径映射或其他身份依据足够时才能沿用 ID。无法判断时记录可能重复，不擅自合并或撤回旧来源。
- Markdown/文本定位用版本绑定的标题路径与行号；PDF 用物理页码并说明是否 OCR；JSON 用字段路径；代码用文件版本和行号。修改后不能让旧行号悄悄指向新内容。
- 读入 PDF 解析结果时检查页码映射；只有文本而无页码时引用真实可定位的文本行号并说明限制，不伪造 PDF 页码。
- 正文可用 Markdown 脚注或来源表。每个关键事实或紧密事实组关联具体来源定位，尤其数值、版本变化和冲突双方。内部 chunk 句柄不能作为用户唯一可见的出处。
- 大文件分批，记录已读与未读范围；不能读取前几页后声称全篇整理完成。

## 阅读正文与内部证据

同一提交只保留一份权威阅读正文及其摘要。正文按主题自然成文；稳定 ID、来源版本、字节位置和主张映射另存或按需展开，不能把内部 facts 数组直接打印为正文目录。正文改动时同步复核证据映射，不额外生成一份不受校验的润色稿。

目录从实际页面及其摘要构建；领域导读可以由 Agent 根据来源范围编写。文档摘要用于理解该文档，主题页用于跨来源归并；综合分析或比较只有用户任务需要且证据允许时才生成。

页面优先显示可理解的来源名、日期、章节/行号；精确 ID/hash/字节区间保留在证据详情。查看器读取结构化提交，不靠 Markdown 标题反推内部类型，不丢掉表格、换行和来源链接。

问题记录采用稳定问题 ID、类型、描述、关联页面/来源与处理状态；同一问题在多页提及仍是一件事。提交完成、语义复核、研究结论是否成立分别记录。语义复核记录实际检查了哪些材料及未读哪些证据，不以一个布尔字段冒充保证。

## 写入与恢复

1. 读取目标版本/hash；把候选、引用和页面改动准备成可检查草稿。原始材料发生变化时重新核对受影响引用。
2. 校验草稿后，在写入入口再次检查源与目标版本。过期即拒绝，保留草稿并重读，不自动覆盖。
3. 使用项目的锁、快照与安全提交设施。单个文件原子替换不等于整批事务；多文件提交必须能辨认已提交与未提交部分。
4. 提交后回读页面与来源映射，再记录成功。人工修改、缺引用、无法保存快照、内容被截断等均作为真实问题保留。
5. 中断后检查 trace、提交记录和实际文件，确定继续点；不要只看到一个 completed 字符串就跳过核对，不因旧锁存在就直接删锁。
6. 回滚应从旧版生成可追踪的新版本，保留发生过回滚的记录；回滚后重新校验当前来源是否仍支持内容，不能把旧引用自动当作当前有效。

若没有能保证上述写入行为的运行工具，仍可在独立的新草稿目录生成页面与报告供试用；必须说明尚未安全应用到已有 Wiki，不用普通覆盖冒充可靠提交。已经存在可用工具时，不因这个条款退回只写建议。

## 人工内容与冲突

人工补充内容没有来源时，保留并标识为人工笔记或待核实，不擅自转为事实，也不删除。已有“人工笔记”区域应原样保留；无区域标记时通过起读版本与差异检查保护。

判断内容删除时检查实际事实、表格行与引用，不用字符长度阈值代替语义判断。无法解释的缩减应拒绝应用。明确的去重或用户授权删减需要在 trace 中记原因。

冲突记录至少说明：冲突双方、各自来源版本与条件、当前处理方式、还需什么证据。不强行归为单一“最新真相”。

## 运行记录最少字段

记录 run ID、输入范围及来源版本、阶段、相关页面、变更理由、旧/新版本、产物路径、错误与未完成项。状态名称可以沿用工程现有约定，但必须区分待处理、草稿、已应用、失败、部分完成。

批次状态不得早于所有必需页及引用检查完成。纯索引可重建但失败仍应报告。保留可恢复的源版本与历史，不自动清理用户文件或历史快照。
