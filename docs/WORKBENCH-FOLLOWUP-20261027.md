## 更新：已接收并合入

2026-10-27 已合入 89a2d24，新工作台支持无 Wiki 的核心阶段文档；默认收尾入口仍未接通。以下保留合并前检查背景，最新结论见 [合并审阅](WORKBENCH-MERGE-REVIEW.md)。

## 合并前检查结果

- `apps/wiki-reader/server.mjs` 只读取已发布 Wiki 快照；`readWorkspace` 无快照抛 NO_SNAPSHOT，启动也先调用此检查。因此目前不能直接展示“只有裁缝方案/DAG、尚无 Wiki”的独立工作区。
- 当前 reader 是本地 HTTP 服务，需要构建产物与启动命令，并非任意流程保存后自动生成的单文件 HTML。
- 当前 Skill 的工作台说明主要表达只读与非必需，没有完整的“收尾默认提供入口”实现。未自动展示是当前交付链缺口，不应要求用户必须完成 Wiki 才有工作台。

## 等新版 UI 后落实

1. 任一 `/init`、`/tailor`、`/exp`、`/story` 完成或部分完成并有产物时，默认提供当前工作区的可用查看入口。已有服务可复用，但先验证绑定的工作区，不能给另一个项目的旧链接。
2. 缺少其他阶段显示“尚无产物”；无 Wiki 但有方案/实验/故事仍可展示。失败和待同步如实可见，不以展示成功代表研究完成。
3. 工作台读取现有文件与 trace，不驱动真实运行，不为凑完整页面自动补跑其他 Skill，也不虚构 Team/指标/图谱关系。
4. UI 未安装、构建或启动失败时给真实错误和 Markdown 产物入口，不返回不可访问的 URL，也不声称工作台已生成。
5. 明确实际交付形态（静态导出或本地服务）、数据版本与刷新方式；不混称自动更新服务和静态快照。

## 接收新版本与 bug 后审阅

用户将提供新版 UI 的仓库/分支或提交及发现的 bug。收到后检查差异、复现步骤、期望与实际结果，先复现再修复；保留首错。重点验收四种单阶段工作区、全流程工作区、无快照/坏快照、增量更新、错误/空状态、跨文件 ID 与任务状态、来源定位、只读边界及 Team 占位。

已知试跑一致性问题见 DS-FLOW-TEST-REVIEW-20261027.md（故事冗长、任务状态漂移、依赖自指等），不要将其简单当作纯 UI bug。

本轮仅检查和登记需求，未修改 reader、Skill 运行逻辑或发布包；不自动拉取、合并或覆盖他人未推送修改。
