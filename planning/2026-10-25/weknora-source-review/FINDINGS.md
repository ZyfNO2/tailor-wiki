# WeKnora 真正做了什么，以及我们哪里偏了

依据见 [源码索引](INDEX.md)，均针对固定版本。以下区分上游事实、当前实现事实和适配判断。

## 1. 上游主链路

```text
解析后的原文块
  → 候选对象/概念（稳定 slug、别名、描述）
  → 文档摘要 + 候选与原文块关联
  → 身份去重、批次目录规划
  → 按页面收集：旧正文 + 新原文块 + 文档语境 + 有效链接
  → 模型编译合并：SUMMARY + 干净 Markdown 正文
  → 保存正文/摘要，同时保存来源与 chunk 关联
  → 链接维护、版本保护、发布
  → 索引导读 + 从实际页面读取的类型/目录/标题/摘要
  → 前端阅读正文；按需进入来源、反链、问题和版本
```

关键不是“多一次润色”。它把最终知识页当作独立成文产物，而不是把内部提取记录直接打印出来。

## 2. 六个应直接遵循的上游设计

1. **页面正文和证据关联分开。** WikiPage 同时有 Content、Summary、SourceRefs、ChunkRefs。合并提示词明确禁止内部 chunk 句柄出现在正文。它没有我们这种每个 fact ID 自动变成二级标题的要求。
2. **文档摘要与知识页不同。** summary 页概括单份文档；entity/concept 页围绕同一对象合并多份材料。synthesis/comparison 是 Agent 产生的分析页，并非自动 ingest 必然生成。不能把材料里的每个章节直接当一种统一页面。
3. **原文证据与来源语境不同。** reduce 读取原文块作为依据，文档摘要只帮助识别来源类型、范围和归属，不能拿来充当新增事实的证据。提示词要求保留自述属性，不能提升为普遍事实。
4. **成文是克制编译，不是自由发挥。** 可以归并、去重、轻度重排；不得为文风扩写、补机制或编造过渡。按材料需要保留自然标题、段落、列表，禁止过度结构化。因此也不能强制所有页面套“定义/机制/实验/下一步”同一模板。
5. **索引有导读，但目录不由模型编造。** WikiIndexIntroPrompt 仅生成领域标题与短介绍。GetIndexView 读取实际页面，前端显示类型、目录、标题和一句话摘要。
6. **阅读不是审计模式。** WikiBrowser 显示标题、summary lead、正文，去掉重复开头标题；页脚显示可打开的来源名称及反向链接。问题对象有 issue_type/description/status 等字段，不靠正文出现“矛盾”计数。

## 3. 当前版本偏离点

| 当前事实 | 后果 | 对应上游依据 |
| --- | --- | --- |
| runtime render 对每个 fact 输出 `## fact.id` | 数据协议泄露为阅读结构，title/alias/scope 冗余 | Content 与元数据分离；WikiPageModifySystemPrompt |
| 字节引用通过后直接提交 | “损伤检测”四字可以挂在完整语义闭环说明下，语义覆盖没有验收 | ChunkCitationPrompt 选择实质讨论；ModifyPrompt 约束新增表述必须被支持 |
| 设计稿、进度报告合并后缺少来源归属措辞 | 设计能力容易变为事实；报告中的数字被叫作本轮“本地实验” | SharedSourceContexts 与自述归属规则 |
| 首页是页面列表，页面是事实块拼接 | 没有先解释材料范围、新旧状态和页面之间的关系 | Summary、IndexIntro、目录摘要 |
| 查看器把所有引文展开，丢失引用 href | 阅读负担重且追溯不方便 | 阅读正文与 open-source-doc 分开 |
| 通过正则匹配“待核实/矛盾”计算问题数 | 标题、重复描述、单一问题的多次提及都可能被计数 | 独立 WikiPageIssue 与问题列表 |

试跑中已经正确保留了 CFD 新旧划分不混用、CPU 与 GPU 证据边界及负结果。这些应保留；不因重设计而抹掉旧页和历史。

## 4. 也不能把上游说成它没有的保证

- 引用映射是候选/页面到 chunk 的关联，不是逐句形式化证明。summary 页只有文档级来源，chunk_refs 为空。我们更细的字节定位是本地增强，不是上游原样搬运。
- classifyChunkCitations 会记录批次失败并继续；无有效引用时 reduce 可用 Details fallback。科研模式应明确未完成，不能把它当精确证据链。
- exactIdentityTarget 存在规范化同标题跨类型复用路径；同名不同实验不能因此自动合并。
- 文档称 Finalize 不用 LLM，但 ProcessWikiFinalize 实际调用 rebuildIndexPage 生成导读。应以代码为准。
- 系统提示词限定“明确修订才覆盖、模糊冲突并列”；用户提示词另有较宽的“prefer newer”措辞。移植时要消除歧义，不以时间新直接判真。
- lint 主要查结构健康，写入保护主要查丢失/截断，不证明内容真实或实验结论成立。

## 5. 对上一轮建议的修正

上一轮建议增加“综合整理”方向正确，但不能另起一个不受来源约束的润色器。应首先恢复上游已有的 **页面级编译合并、来源归属、摘要与目录、阅读/证据分离**；额外的科研审查明确作为本地约束，不冒充上游功能。
