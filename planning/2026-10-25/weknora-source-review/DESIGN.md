## 目标

同一份 Wiki 同时服务人类阅读和 Agent 检索：页面以自然 Markdown 成文，来源与精确定位可追溯，运行与问题有独立记录。文件仍是事实来源，工作台只读。移植范围是 Wiki 主链路，保留上游可复核出处，避免再凭印象实现。

## 文件数据设计方向

恢复四个明确角色，不建立互相竞争的两套正文：

- **页面**：稳定标识、显示标题、一句话摘要、类型/分类、自然 Markdown 正文。正文是本次提交唯一阅读内容。
- **证据**：正文段落或主张到来源版本/原文定位的映射。现有 facts 可作为内部稳定引用单元，不能直接决定页面标题或阅读顺序；正文变化必须同步校验映射，不能展示一份未经核查的额外改写稿。
- **问题**：唯一 issue ID、类型、描述、影响页面/证据、状态。未解决问题允许保留，但不能靠关键词重复计数。
- **运行与历史**：快照、提交、trace、来源变化和实际检查结果。写入完成、语义复核情况、未解决问题分别显示，不能一个 complete 概括全部。

具体字段与旧 schema 迁移由实施时确定，原则为兼容读取旧快照、新版另提交、不原地改历史。任何默认“已审查”或自动补空证据都不允许。

## 验收

- 读总览能知道材料是什么时期、哪些是设计、哪些是报告记录；不读 trace 也能理解主要内容。
- 任意一条数字或能力陈述能打开足够支持它的来源上下文；仅包含关键词的引文不能通过人工/Agent 语义复核。
- 第三章 CPU 结果与 GPU 待办不混淆，CFD 新旧划分不混表；语义审查记录明确限定读取范围。
- 正文没有 `## title` / `## scope` / fact ID 标题；来源显示可识别名称，精确位置按需展开。
- 问题按独立 issue 去重，文中出现“矛盾”不自动新建问题；未核实不伪装为科学否定。
- 重复输入不增内容版本，单来源更新只改受影响内容，人工笔记和旧快照不丢失，已有并发/恢复测试继续通过。
- 前端若宣称“剪枝”，必须能给出原组件路径、保留代码、裁去能力、接口适配和许可证；若仍是自写投影则如实标明。
