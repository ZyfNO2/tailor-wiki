## 2. 产品定位与底线

面向个人科研工作者：把论文与笔记整理为知识，从知识提出方法组合，安排实验，查看执行证据，再组织研究叙事。工作台像研究过程的观察台，能看清“依据是什么、做到哪里、哪里卡住、产物在哪里”。

- 原始材料、Wiki 快照、方案文件、实验结果和 trace 是事实来源；工作台只展示，不维护另一套研究状态。
- 当前设计不提供启动训练、派发 Agent、在线改实验结果、拖拽改变真实依赖等操作。导航、搜索、筛选、展开、画布缩放和本地布局可以交互。
- 四个独立 Skill：wiki-maintain、academic-tailor、experiment-design、research-story。没有总 Skill、没有必须按顺序运行的流水线。
- “创新点”是学术裁缝产出的研究假设/方法差异视图，不新建独立创新 Skill。
- 用自然语言、标题、摘要作为主要信息；ID、hash、字节范围、原始 trace 放详情，不让技术字段占满正文。
- 未运行显示未运行，未知显示未知；模拟、历史报告、本轮真实执行必须可辨认。执行成功不等于研究假设成立。

## 3. 建议导航与核心路径

建议一级导航：项目概览、知识库、研究方案、实验、DAG 白板、任务与 Team、研究叙事。来源、trace、版本与问题可以作为二级页或上下文抽屉，避免每种内部对象都占一级导航。

核心路径：从 Wiki 的证据条目打开关联裁缝方案 → 查看假设与模块来源 → 查看实验计划和实际 Run → 查看审查结论 → 打开故事主线及证据缺口。允许从任意产物进入，不强制前一阶段完成。

全局上下文显示当前项目、数据来自哪个工作区、快照/读取时间；失效或读取失败清晰提示。项目切换不得混用不同工作区的成员、运行和结果。

## 4. 页面需求

### 项目概览

简短研究问题、当前选定方案、最近产物、阻塞事项、最近变更。进度以实际任务计数和范围展示，不生成没有依据的总体百分比。入口直接定位未处理材料、阻塞实验或待审结果。无数据时解释应由哪个文件/Skill 提供，不填示例成绩冒充真实数据。

### Wiki 阅读与维护覆盖

左侧目录/搜索，中间自然正文，右侧或抽屉呈现证据、关联与问题。正文支持标题、列表、表格、代码、数学公式和页间链接，不按 fact ID 分章节。

- 每页显示标题、一句话摘要、类型、版本、相关主题与反向链接。
- 点击引用可见来源文件名、材料性质/日期、原文片段、页码/行号和版本；更深层展开 ID/hash/字节范围。不能直接打开本机文件时提供复制路径与内嵌片段。
- 历史列表、两版正文差异、来源变化；没有历史显示只有一个版本，不显示虚构差异。
- 问题按独立事项列出：矛盾双方、适用条件、证据、状态、解决记录。同一问题跨多页只计一次。
- 覆盖面板显示用户指定范围、来源总数、本轮处理、未变复用、部分处理、失败/不支持、明确排除；各状态可筛到文件列表，显示未读范围和原因。
- 文件提交、全量覆盖、语义复核分别显示，不能用一个绿色“完成”代替三者。

### 知识图谱

图谱表达“知识与证据的关系”，不是任务执行顺序。节点包括来源、概念/方法 Wiki 页、研究方案/假设、实验和结论；默认先显示当前页面的一跳邻居，用户再展开，避免整库毛线团。

关系使用有方向、有类型的边，如来源支持、引用、相关、对比、冲突、方案采用模块、实验检验假设。共现或语义相似不能标成因果或支持关系；未知关系不猜。

支持搜索定位、按节点/关系类型筛选、缩放/平移/适配、路径高亮、节点详情和跳回原文。冲突关系有文字/图标及颜色，节点可显示证据状态。没有边数据时显示尚无关系证据，不自动生成看似真实的连线。提供等价列表视图，便于小屏和阅读器使用。

### 学术裁缝与创新方案

读取 TAILOR.md 或其解析投影。首页是少量方案卡，详情展示研究问题、现有失败证据、基线 A、模块 b/c、来源、接入位置、具体改动、风险和待验证假设。

用一个简洁数据流图展示插入/替换/并联位置，旁边显示原方法与本项目改动，不把模块换名等同新颖性。支持方案并排比较：依据、实现成本、风险、所需材料、预期验证。

必须分别显示：用户决策（建议中/已选/授权代选）、技术就绪（可设计/可试跑/可完整执行）、证据状态。详情有接口、数据、资源、原文核对四项检查，缺口链接到受阻步骤。创新主张标“待证假设”或证据支持范围，不生成“创新评分”。

### 实验设计与实验结果

计划读取 EXPERIMENT-PLAN.md：每行是待验证问题、变体/对照、数据划分、配置、依赖、主指标、保护指标、预算、成功/失败条件、预期产物。A、A+b、A+c、A+b+c 可作为示例，不对所有方案强制四格。

计划与实际运行分栏或分标签。一个计划可以有多次 Run，保留失败、取消和淘汰尝试，不只展示最佳结果。Run 详情含代码/数据版本、实际资源、时间、配置、日志、原始指标、产物链接和首错。

对比前显示协议是否可比：指标定义/方向/聚合、数据划分与预算。不可比给原因，不强行排行榜。缺失指标用空缺说明，不填 0；模拟结果单独标识。结果判定包括支持、反驳、证据不足，独立于进程状态。图表设计需支持误差范围和负结果，无真实数据时展示空状态而非伪造曲线。

### DAG 白板

DAG 表达“任务/产物依赖”，与知识图谱分开。节点可以是材料整理、方案核验、实验计划、基线运行、单模块实验、组合实验、结果审查、故事更新；不要求所有项目都具备这些节点。

节点摘要：任务名、类型、执行状态、负责人/成员、输入输出、阻塞原因。点击展开来源文件与 trace；边说明“等待什么产物/条件”，而不是只画箭头。相关关系不得伪装依赖。

支持只读缩放、平移、折叠子图、按状态/成员筛选、定位当前节点、查看上下游影响。布局拖动如有，仅改变视图，不改变文件依赖；不提供会误认为已真实派发/重排执行的操作。

依赖环、缺失节点、失效产物和读取失败作为错误状态展示；不得自动删边让图看起来正确。节点完成但审查未通过时，明确后续仍可能受阻。

### 任务状态与 Team

任务提供列表为主、看板为辅：任务标识、目标、当前阶段、负责人、依赖、执行状态、审查状态、最近事件、产物。状态建议映射待执行、运行中、阻塞、失败、取消、完成、未知；以实际适配字段为准，不强迫后端新增状态。

Team 展示真实成员或 Agent 的名称、角色、模型（有记录才显示）、当前任务、运行状态、最近活动时间、已交付产物、受阻原因。区分“建议的分工”与“已存在的成员/会话”，不能把角色模板显示为正在工作的 Agent。

成员详情关联任务、会话标识/可用链接、trace 和产物；展示事件摘要而非模型隐含思维。暂无心跳只表示状态陈旧/未知，不擅自判离线或失败。多人同时修改同一文件时展示已记录的冲突，不虚构调度系统。

当前版本只读，不做聊天、邀请成员、派发、重试、暂停按钮；可设计未来操作位置但标明后置，不混进本轮验收。

### 讲故事与研究叙事

读取 STORY-PLAN.md，展示一句话主线、问题→方法变化→验证→边界的结构，以及贡献—证据表。每个贡献链接相关方案、实验 Run、原始来源和缺口。

区分待验证机制、实际观察、已有支持的解释与备选解释。图表安排展示拟回答的问题、已有素材、待制作状态；没有图就不显示成已完成 Figure。

支持查看不同主线建议及取舍、证据缺口列表、跳转实验计划。不默认生成或修改论文正文，不把叙事润色变成结果修改；文献新颖性、性能收益和机制解释分别呈现。

## 5. 数据对应关系（设计对象，不是冻结 API）

| 对象 | 事实来源 | 最少展示字段 |
| --- | --- | --- |
| Wiki 页面/来源/版本/问题 | Wiki 已发布快照及引用记录 | 稳定标识、标题、正文/摘要、来源版本、关系、复核状态 |
| 方法方案/假设 | TAILOR.md | 方案标识、A/b/c、依据、检查项、用户决策、就绪、缺口 |
| 实验计划 | EXPERIMENT-PLAN.md | 实验标识、假设、对照、协议、依赖、预算、判据 |
| Run/审查 | 原始结果、日志、trace、审查文件 | Run 标识、对应方案/计划版本、状态、指标、判断、证据路径 |
| 任务/Team | 真实任务/会话记录及 trace | 标识、职责、指派、时间、状态、产物；不存在则未知 |
| 故事 | STORY-PLAN.md | 主线、贡献、证据关联、未证实项、图表计划 |

同一对象在卡片、图谱、DAG 和列表中使用同一标识与来源。研究方案、计划实验、单次 Run、审查决定不是同一个对象。视图可从文件派生，不在浏览器保存第二套权威状态。解析失败应显示错误和原文件入口。

## 6. 需要设计方交付什么

1. 信息架构与桌面主流程；1440px 主稿，另给窄屏折叠方案。
2. 高保真页面：概览、Wiki、知识图谱、裁缝方案详情、实验计划/Run、DAG、任务/Team、故事与证据。
3. 关键交互原型：引用展开、版本比较、图谱邻居展开、DAG 节点详情、任务→成员→产物、方案→实验→故事跳转。
4. 组件与状态规范：标题/正文/表格/标签/抽屉/画布；正常、空、加载、失败、部分完成、数据陈旧、来源缺失、待核实。
5. 可转交的静态 HTML 原型或设计源文件，所有示例标识清楚。真实操作与纯展示有明确边界。

建议分两组交付：先 Wiki、方案、实验、任务基础阅读；再图谱、DAG、Team 和故事关联。图谱与白板不能牺牲正文阅读，也不要求第一轮就做复杂动画。

## 7. 工作台验收清单

- [ ] 从 Wiki 正文能定位具体原文，并返回阅读位置；表格和公式不丢失。
- [ ] 未处理材料、失败原因与明确排除可逐项查看；局部完成不显示全量成功。
- [ ] 来源为历史报告的结果不会显示成本轮真实实验。
- [ ] 方案的用户决策、就绪程度与证据状态同时可辨认。
- [ ] 方案→计划→多个 Run→审查→故事能双向定位，缺失环节明确提示。
- [ ] 图谱与 DAG 各自表达关系和依赖，图上信息能在列表中查到。
- [ ] 任务完成、研究审查和假设成立不会合并为同一个成功状态。
- [ ] Team 不存在或状态陈旧时正确显示，成员产物能追溯真实记录。
- [ ] 只读点击不修改来源、启动训练或派发任务；视图布局不修改 DAG 文件。
- [ ] 空库、无历史、断链、读取错误、部分运行、负结果都有可用界面。
- [ ] 键盘可达、焦点可见，状态不只靠颜色，正文可读、详情可收起。
