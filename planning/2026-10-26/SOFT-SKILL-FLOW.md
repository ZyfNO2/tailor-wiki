# 按用户流程图调整独立 Skill 编排

依据：2026-10-26 用户提供的 Excalidraw 剪贴板。图中 /talior 统一为 /tailor。

| 意图 | 实际 Skill | 推荐输入（非硬前置） | 交付 |
| --- | --- | --- | --- |
| /init | wiki-maintain | 指定范围材料、已有 Wiki/进度；无材料时询问目标与联网意愿 | Wiki、覆盖清单、来源、恢复点 |
| /tailor | academic-tailor | Wiki 或直接论文/代码/方案 | TAILOR.md 与任务 DAG |
| /exp | experiment-design | 裁缝方案/DAG 或直接方法方案/已有实验 | 实验计划；获执行授权且工具可用后接续 Run 和结果 |
| /story | research-story | 方法设计、实验计划或实际结果 | 待验证或有证据支持的 STORY-PLAN.md |

主线推荐按表顺序推进；任何阶段都可独立进入。设计后即可讲故事，已有结果可直接分析。Skill 软依赖不消除实验本身的数据/接口/资源前置。不存在总 Skill 或强制串行研究链；Team 是未来可选执行者。

用户追加确认：实验与故事之后默认增量维护 Wiki。实验计划/Run/结果/审查与 STORY-PLAN 保存后，以变化产物为范围更新受影响 Wiki；不全库重写，不将叙事自述当科学证据。交付与同步状态独立，失败保留待同步清单；维护不递归启动研究任务。明确跳过遵守用户选择；缺少维护能力或目标位置不明如实处理，不虚报同步成功。这是收尾行为，不是进入实验/故事的前置门禁。

DAG 无现成格式时用 RESEARCH-DAG.md：稳定任务节点表及带产物/条件的依赖边表，可附 Mermaid。模块数据流与任务 DAG 分开；不能把所有关联变成前置，也不提前登记成员和运行成功。未来前端适配现有实际文件，不从展示层另建状态源。

## Skill 以外需要补的工程工作

1. 宿主短命令映射：/init、/tailor、/exp、/story 对应四个现有 Skill，保留原名称兼容；检查 /init 是否与宿主命令冲突。当前只是意图约定，未注册。
2. 文件读取适配：工作台统一读取 Wiki、TAILOR、DAG、EXPERIMENT-PLAN、Run/trace、STORY-PLAN；沿用稳定方案/任务/运行标识。Markdown 先可用，待真实接线需要时再定机器格式。
3. DAG 与界面：白板呈现任务依赖、阻塞、产物；与知识图谱分开。原 WeKnora Vue 源码剪枝任务中断，仍需完成或由用户新设计接替。已有 HTML 为示例原型。
4. 真正实验执行：/exp 的设计不生成实验数据；执行入口、环境检查、日志/指标回写和恢复需要现有执行能力或后续实现。Team 调度可后置，不阻塞单 Agent/人工实验。
5. 验收：安装新版后检查有材料恢复、无材料询问、无 Wiki 直接裁缝、方案直接讲故事、已有结果直接 /exp、缺输入仅阻塞相关分支、重复维护不漂移。
6. 既有缺口：Wiki 指定范围覆盖仍主要由 Skill 与 trace 对账保证，跨目录覆盖强制门禁尚未实现；本轮没有将其伪装成已完成。

本轮范围：四个 Skill 正文及使用说明、分发包；不注册宿主命令、不实现前端/Team、不运行真实实验、不改用户论文。
